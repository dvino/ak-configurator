## Current state

**Accepted limited offline scope (2026-11-03).** Independent reviewer `b07_session_review` accepted the frozen B07 source/host checkpoint after independently matching the B07-SOURCE report SHA256 and all 64 listed source-file hashes. The reviewer accepted test and lint results as reported, without rerunning them. This accepts only the finite-unlock and shared logical owner-binding offline scope recorded here. It does not attest source-to-binary linkage, a physical USB descriptor, native window behavior, physical input/device behavior, macOS, Q02 parent-death/helper lifetime, or release readiness. H03 live unlock remains separately gated. B06’s earlier accepted checkpoint did not cover this later shared owner-binding correction.

Before B07, unlock status polling depended on UI repaint and errors could be retried automatically. The current B07 worker uses one shared session and a 200 ms observation cadence independent of UI frames. Denial, error and disconnect are terminal; they do not trigger automatic polling or retry. Already-confirmed unlocked state succeeds immediately.

For a new start, the 15-second dispatch deadline begins only after FE06 acknowledgement. An already-running operation must not send START again and has a separate 15-second observation budget after initial status. FE07 can issue FE05 confirmation, so cancellation and committed exit must be checked at every packet boundary. The deadline bounds dispatch. Virtual tests exercise the dispatch timing; the Windows packet caller budgets are 4 seconds for USB and 8 seconds for BLE. End-to-end scheduling/reaper tail has not been measured, so no hard 15-second completion claim is made.

Normal non-AK USB FE05/06/07 helpers currently follow transport retry policy; the authorized narrow change is one attempt. A first transport-only implementation added one-attempt dispatch and a guarded polling callback, before work moved into the shared finite worker. AK820 and BLE already use one attempt. No generic non-AK820/Wasm behavior changes beyond this attempt limit. Reuse B06’s guarded exit lifecycle, renaming the RGB-specific field if required. Committed exit prevents later packets; ending a host wait does not cancel firmware work. Beta.5 write denial and the installer’s fresh Esc+left-Control confirmation flow remain unchanged.

The Windows path uses the existing `HidProxy`. Its per-packet caller budget is 4 seconds for USB and 8 seconds for BLE, covering queue, write and read. The 15-second unlock deadline stops new dispatch; the end-to-end scheduling/reaper tail has not been measured. This is not a hard real-time or end-to-end 15-second guarantee. A local 500 ms read timeout alone would not bound a write blocked inside the child process; the existing proxy isolates that transport call. This audit is Windows-specific and makes no Linux physical-runtime claim.

The timing tests use the actual worker with shared fake HID delays (5 seconds for initial status and 8 seconds for START), timestamped 200 ms polling (74 observations), and the FE06 deadline origin; they use no physical sleep, keypress or HID. The progress test deliberately publishes 3 then 5 without resetting the original deadline. At admission and completion, the selected logical target is compared with stored `ProxySlot.device`; when the helper opens, it validates the actual target claim once. This is not a per-packet physical descriptor measurement. `TestHid.boundDevice` defaults to `None` and fails closed; there is no missing-owner test bypass. Wrong-owner and missing-selection tests verify zero packets for RGB and unlock. Windows GUI proxy identity metadata is authoritative; unsupported Local/BLE paths without owner proof fail closed. No second engine or relaxation of known-image/source policy is allowed. B06’s accepted historical checkpoint did not cover this later shared-path correction.

USB transport timeout must remain distinguishable from disconnected: preserve the actual error chain privately and expose only bounded phase/cause labels in the UI, without raw paths or payloads. This is a real cause-classification requirement, not a synthetic generic message.
