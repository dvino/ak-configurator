# B06 — bounded RGB worker

Russian: [RU](../ru/session-evidence/B06.md).

## Current state

**B06’s limited offline RGB worker scope was accepted on 2026-11-03** by independent reviewer `b06_ui_review` after review of EN/RU documentation, reported test results, the direct UI test run and the listed source-file hashes. This accepts offline B stage 3 evidence only. It does not qualify a native OS window, physical device, macOS or release readiness, or attest that the reviewed test binary was built from the inventoried sources. Generic non-AK820 and Wasm behavior remains outside the change. At the B06 checkpoint B07 was still in progress; it was subsequently accepted for its limited offline scope as recorded in [B07 evidence](B07.md).

A later B07 review identified an actual-owner binding gap in the shared RGB admission/drain/completion path. The accepted B06 checkpoint did not test that correction; the narrow owner-query fix and zero-packet cases for RGB are being handled with B07 and are not covered retroactively by this acceptance.

The readiness audit found existing readback and policy checks that must be reused: `src/hid_ak820.rs` already guards FD01 before and after the operation, and `ak820_verify_write` provides existing SET/GET, SAVE/GET and NVM readback behavior. Do not add a duplicate GET or a second engine.

The UI worker can cancel before method dispatch; once a method starts, exiting the UI worker cannot stop its internal transport packets. A narrowly scoped cancellation hook inside the existing transport/guard is authorized so exit can prevent packets that have not crossed the operation boundary. Preserve exactly one SET and at most one existing-policy SAVE per submitted logical operation. Keep required verification/status packets unless cancellation or exit occurs before their boundary; then stop further packets and report a fail-stop uncertain result. Never retry, replay, or silently continue a submitted operation after exit.

Disable RGB controls while an operation is submitted. Keep at most one submitted command and one replaceable unsent draft; coalesce only the unsent draft. Exit remains nonblocking with a bounded wait for in-flight work and sends no later packet or draft. The authorization guard and beta.5 write denial stay unchanged. H02 physical qualification remains separate and pending.

The first default-feature RGB test run exposed a transport-boundary issue in a SAVE/GET fault fixture: the Vial RGB GET echo at packet 7 (`[8, 0x41]`) was validated only after the later NVM readback packet 8. This GET echo is distinct from the FD01 pre/post status checks. The code was changed to validate the GET echo before issuing NVM readback; a valid-header value mismatch still follows existing policy and reaches packet 8. This is not a count-based guard. A second test snapshot passed after this change, but preceded the close-handling correction below.

The independent UI review also flagged exact returned-image verification, raw/private error text, Quit flushing before cancellation, and deferred writes after exit. The author added exact returned-image checks and bounded EN/RU messages. A later review found that normal close actions (tray, Ask/cancel and unlock) incorrectly set permanent RGB exit/poll-only state. The correction applies that state only to committed Close/Quit and helper handoff; ordinary tray, Ask/cancel, unlock and prior non-RGB behavior are preserved. The latest UI review found no blocker: committed exit does not adopt the handle; the headless native-host UI model uses exit-first guard/logic and polls on exit; close-pass feedback is emitted. Tests cover same-generation swaps, bounded repeated reads after mismatch and stale generations preserving newer status/recovery. A separate Quit-request test runs at least 5.1 seconds while background updates continue each frame; zero packets are emitted before and after completion and an unrelated QMK draft remains unsent. A separate headless native-host test dispatches the application window-close event. These tests do not exercise a native OS window, window manager or actual HID.
