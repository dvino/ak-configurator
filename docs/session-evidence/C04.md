## Operation behavior and limits

Prepare is available through the existing `--mcp-access=read-only` CLI because it performs bounded local artifact work and no device mutation. The CLI has no new scope flag. The async request returns an operation ID when accepted; the existing `ak820_operation` `status` and `cancel` actions expose progress and terminal result. For queued work, `lease_held` is `null` (unknown), not false. Prepare uses the existing engine owner when present and does not acquire a HID lease on worker start. The process bounds retained operations to 32 for its lifetime. If the accepted ID is lost before the transport receipt reaches the caller, there is no list/get action to rediscover it.

The builder strictly parses canonical closed plans, rejects duplicate/unknown input fields, stale or mutated bindings, expired plans and unsupported admissions. It checks selected-release withdrawal using the read-only blocked-pins path, which does not create, migrate or write pin state. Loader-source inspection is bounded. The implementation does not create approval, expose execute, or open a HID writer. The read-only input guard has its own scope and evidence in [C04 input guard evidence](C04-INPUT-GUARD.md).

Native B11 install preparation semantics are reused. Beta.3 remains denied for production admission. Beta.4 cases in the pure model are offline coverage and do not qualify beta.4 for live MCP. Sticky withdrawal blocks are preserved. The read-only source-observation check bounds the loader but does not establish bootstrap admission. Ownership of persisted release-observation file ancestors and their owner could not be proven. The C02 store limits remain 1 MiB per plan, 16 MiB per backup and 100 retained artifacts, with no automatic eviction. Windows reports `DirectoryFlushUnsupported`; this is a durability limit, not evidence of power-loss durability.
