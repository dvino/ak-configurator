## Current source contract

The active source catalog supports Main, Game, Mmo, Typing, Code, Pointer, Onehand, Creative, Shortcuts and Multios. Every profile uses schema03 (0x082003), with exact packed CODE/settings identity, counts, QSIDs, source-aware keycode restrictions and explicit directional transitions. A full-image/settings loader verifies the target before enabling edits, reads required settings and fails closed. Unchanged defaults do not cause a setter; typed-module changes compare the full NVM before and after to preserve neighboring data. A timeout, storage fault or failed readback stops the session.

The offline project format is v2 and pins the target release, catalog and Intel HEX image. Beta1 v1 projects are rejected for deliberate manual migration. The historical source registry is limited to three schema02 backup identities and has no aliases or live beta1 path. Alpha3 remains an exact separate compatibility path.

The editor provides ten profile examples, schema03 typed controls, and profile-specific built-in RGB effects. The v1 static palette format remains intact. An additive scene editor uses format v2 and supports at most 16 ordered/enabled layers, masks over 82 LEDs, Solid, Gradient, Wave, Breathing and Rain effects, horizontal/vertical axes, opacity and 250–60000 ms periods. It includes a local preview, quiet-hours brightness cap using local wall-clock time (inclusive start, exclusive end; overnight intervals supported), click/Ctrl/Cmd/Shift selection, and bounded undo/redo history of 32 draft states. Drag selection is not implemented. Scenes and palettes are local files; no persistent scheduler daemon or automatic playback start is provided.

Live scene playback is owned by the existing HID session and uses a latest-frame queue of one with a conservative maximum of 10 frames/s. This is an application limit, not a hardware-qualified frame rate. Settings, backup and modal/connect-priority work pause playback and drop pending frames; playback resumes with a fresh frame only if the same session remains intact. A monotonic UI gap over two seconds, a wall-clock jump over two seconds, or a backward wall-clock jump stops playback and requires explicit restart. A pending Off request expires across those gap checks, preventing a stale black frame after a long suspension. Disconnect, session-generation/profile change or error stops playback without retry or restoration. Each frame checks mode ownership; physical RGB mode, speed or HSV changes stop playback without overwrite. Stop cancels unsent packets and leaves colors already sent in RAM. Explicit Off stops and sends one black frame only in a safe intact session; it does not persist. No built-in effect is restored automatically; a built-in must be selected explicitly. The application does not save NVM per frame, and firmware offers no palette getter or atomic frame commit. Previously recorded RGB host validation passed (35 tests); Linux demo verification showed animated preview and exact JSON save/reload for 82 colors and two layers. Hardware timing, CPU/memory and per-OS behavior remain unqualified. Direct palette editing remains limited to Main, Game, Mmo and Creative; the keyboard has 82 LEDs for 83 physical keys and encoder press has no LED. Direct caps V at 160, uses ten packets of at most nine LEDs and requires explicit RAM apply. Saved mode 5 maps to Direct for those four profiles and Reactive for the other six.

The RGB research and five-phase implementation guide is [RGB-PLAN.md](RGB-PLAN.md); its Russian counterpart is [ru/RGB-PLAN.md](ru/RGB-PLAN.md). The RGB guide remains the detailed planning source.

## Backup, restore and reset

Complete beta2 capture uses the existing HID owner, reconciles live getters with saved NVM, retains inactive typed bytes, and repeats NVM, ROM-manifest and storage checks. A snapshot remains in memory until explicitly saved. Private staged publication validates a reread and never replaces an existing backup. Bounded history checks at most 128 immediate backup folders and 1024 root entries, fully validates entries and pins their manifest digest for reopen.

Restore requires a fresh complete capture equal to the immutable preview, a verified safety backup, a fresh three-second Esc + left Control hold, and source reopen before the first setter. Each whitelisted setter runs once with acknowledgement, getter and complete NVM checks; final ROM, getters, repeated NVM and manifest are checked. Read-only sessions refuse mutation. Errors stop without retry or automatic rollback, retain safety references and require explicit reread; RGB does not restart automatically.

Reset now derives the current exact image's release defaults from bundled public sources and presents a separate preview. It uses the same safety-backup, fresh-confirmation and verified one-attempt executor. Supported keys, both encoder directions, macros, lighting and active modules reset; inactive, reserved and inaccessible values remain intact. This is a settings reset, not factory firmware rollback. Explicit backup deletion reopens the selected archive with its manifest digest pinned, validates it again and removes only the known files after a separate permanent-deletion confirmation. It does not recursively remove unrelated folders. A filesystem error can leave a partially deleted folder and is reported.

Backup operations support Linux, macOS and Windows. Unix paths are directory anchored; macOS rejects parent ACLs. Windows uses local-drive handle-relative operations, rejects reparse points/hard links, applies a private user/SYSTEM ACL, syncs files and publishes without replacement. Unix parent-directory fsync semantics are not promised on Windows; UNC/device paths are unsupported. Historical Windows GNU and macOS arm64 adapter typechecks are not current full-app build or runtime evidence.

## Firmware installation and local recovery

A separate native installation window is now connected to source implementations for preparation and execution. It supports the ten pinned beta2 profiles using bundled public IHX/map files or an exact prepared local payload. Source hashes, compiled defaults, packed CODE identity, schema and protected regions are checked before erase. The public files do not include OEM helper bytes. For initial bundled installation from an exactly validated fresh OEM capture, that capture supplies the required private bytes locally without a preexisting ROM file; explicit defaults are required. Project-firmware updates and prepared payload files still require a supported personal OEM reference. An invalid supplied reference is rejected and never replaced by an automatic fallback. The local **Firmware files** three-file checker remains available separately and performs no installation.

The installer binds an immutable preview to a fresh 65,536-byte device read, exact 51,136-byte payload, target/settings choice and confirmation pin. It attempts complete settings capture even when defaults are selected; continuing after its failure requires the explicit defaults choice. Available settings are preserved or migrated only through the reviewed image/transition rules. Available complete settings and the fresh full-ROM safety snapshot are saved and reread before erase. When recovery ownership is recorded, the trusted local recovery-manifest registry is also synced and reread before erase. Any required safety-data or registry failure stops execution and retains the paths of data already saved. Confirmation uses a fresh physical hold on supported project firmware and a separate explicit start for OEM. The native helper owns the physical port across application/loader transitions, sends the bounded loader sequence once, reconnects and compares the complete ROM. Cancellation is available before erase; ordinary close is blocked while the installer owns its transaction. Firmware and settings outcomes remain separate. Any failure stops without blind retry, reset or automatic recovery.

OEM rollback requires a previously recorded local recovery folder, pinned manifest and first-capture ownership evidence bound to the unit/USB port. Protected regions are compared with the fresh device snapshot. Missing ownership evidence, including a unit without a usable serial, blocks rollback; an arbitrary filename or VID/PID is insufficient. OEM ROM, settings and recovery receipts remain local.

Release admission is pinned to v0.6.0-beta.2 and requires explicit prerelease opt-in. An explicit online check compares the published project release/assets with the reviewed metadata and saves withdrawal/change observations. A known block persists and also blocks a manually selected payload. Network failure retains the last known state; offline metadata cannot establish that a later withdrawal has not occurred. This is not a complete latest-stable or historical-release browser, and arbitrary custom builds remain blocked.

## OS layout helper and operation ownership

An opt-in FD02 v1 helper maps detected EN/RU layouts to off, on or slow breathing; normal mode releases the override. Preferences are local application settings, separate from keyboard backups/reset. The GUI worker borrows the verified HID owner; strict reply validation and nominal one-second refreshes do not touch NVM. Unknown/unmapped layouts release indication. Unsupported Wayland compositors remain unknown rather than being guessed as English. A timeout or bad reply stops refresh until identity/settings are checked again.

Explicit `--ak820-helper` starts a background loop without creating the full GUI. It checks saved opt-in, requires exactly one USB candidate, loads the exact image/settings and retains only the HID owner. A faulted endpoint stays blocked until successful enumeration proves disappearance or a different instance token; a timer does not regrant it. A request to open the interface releases indication and hands off within the same process/instance lock. Disable and orderly exit release the override where possible; transport loss falls back to firmware's 3000-ms lease. The existing autostart setting remains separate. The explicit close-interface action and ordinary Close with the helper enabled return from the native GUI, drop the app/renderer/windows and enter the helper; explicit Quit exits. Reopening recreates the GUI in the same process. Opted-in minimized/autostart launch also avoids initial GUI creation. These lifecycle paths require separate platform verification.

The shared owner gate excludes settings, backup, restore/reset, RGB, helper and installer overlap. Native installation retains the cooperative per-device lease through loader/reconnect. External Vial software does not honor this advisory guard. Browser/helper interoperation remains part of the later browser stage.

## Application updates

**About AK Configurator → Application updates** opens an explicit check/download window. Stable releases are the default; prereleases require a separate checkbox. Checking performs no installation. The client selects the greatest eligible canonical version from at most 100 published project releases and requires its complete six-target `app-update-index.json`. Missing, changed, duplicate or inconsistent metadata fails closed; it does not silently select an older release.

The index and selected archive must match the GitHub API asset size and SHA256 digest, exact project release URL, OS/architecture and filename. Metadata is bounded to 2 MiB, packages to 512 MiB; HTTPS redirects are checked individually against the permitted GitHub hosts. Before download, the release/index is checked again. Only a version newer than the running application can be downloaded through this update path. SHA256 checks integrity against GitHub metadata; it does not provide an independent publisher signature.

Download uses a private temporary file, checks the complete size/hash, syncs and rereads it, then publishes without replacing an existing cache object. An existing cache file is accepted only after another complete hash/size check. Cancel or closing the update window retires the worker; an outstanding HTTP request may take its timeout to return. A late cancellation can leave a fully checked cache file. The application displays its path and per-user installation guidance; it never starts an installer or sends a keyboard command. Installation replaces application files while preserving the separate helper preferences. Firmware selection, installation and settings restoration remain separate actions.

The native `--self-check [--output NEW_JSON_FILE]` command runs before preferences, instance signalling, HID/proxy setup and GUI startup. It validates the ten bundled public IHX/map/default-settings contracts and application icon, reports the executable version and target, and exits. Its report contains no device/user data. An existing output file and mixed device/GUI arguments are rejected. This proves only the executed public-input probe; it does not prove GUI, USB, packed firmware or persistence behavior.
