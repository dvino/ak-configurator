## Current source contract

The active source catalog supports Main, Game, Mmo, Typing, Code, Pointer, Onehand, Creative, Shortcuts and Multios. Every profile uses schema03 (0x082003), with exact packed CODE/settings identity, counts, QSIDs, source-aware keycode restrictions and explicit directional transitions. A full-image/settings loader verifies the target before enabling edits, reads required settings and fails closed. Unchanged defaults do not cause a setter; typed-module changes compare the full NVM before and after to preserve neighboring data. A timeout, storage fault or failed readback stops the session.

The offline project format is v2 and pins the target release, catalog and Intel HEX image. Beta1 v1 projects are rejected for deliberate manual migration. The historical source registry is limited to three schema02 backup identities and has no aliases or live beta1 path. Alpha3 remains an exact separate compatibility path.

The editor provides ten profile examples, schema03 typed controls, and profile-specific built-in RGB effects. The v1 static palette format remains intact. An additive scene editor uses format v2 and supports at most 16 ordered/enabled layers, masks over 82 LEDs, Solid, Gradient, Wave, Breathing and Rain effects, horizontal/vertical axes, opacity and 250–60000 ms periods. It includes a local preview, quiet-hours brightness cap using local wall-clock time (inclusive start, exclusive end; overnight intervals supported), click/Ctrl/Cmd/Shift selection, and bounded undo/redo history of 32 draft states. Drag selection is not implemented. Scenes and palettes are local files; no persistent scheduler daemon or automatic playback start is provided.

Live scene playback is owned by the existing HID session and uses a latest-frame queue of one with a conservative maximum of 10 frames/s. This is an application limit, not a hardware-qualified frame rate. Settings, backup and modal/connect-priority work pause playback and drop pending frames; playback resumes with a fresh frame only if the same session remains intact. A monotonic UI gap over two seconds, a wall-clock jump over two seconds, or a backward wall-clock jump stops playback and requires explicit restart. A pending Off request expires across those gap checks, preventing a stale black frame after a long suspension. Disconnect, session-generation/profile change or error stops playback without retry or restoration. Each frame checks mode ownership; physical RGB mode, speed or HSV changes stop playback without overwrite. Stop cancels unsent packets and leaves colors already sent in RAM. Explicit Off stops and sends one black frame only in a safe intact session; it does not persist. No built-in effect is restored automatically; a built-in must be selected explicitly. The application does not save NVM per frame, and firmware offers no palette getter or atomic frame commit. Focused RGB host validation has passed (35 tests); Linux demo verification showed animated preview and exact JSON save/reload for 82 colors and two layers. Hardware timing, CPU/memory and per-OS behavior remain unqualified. Direct palette editing remains limited to Main, Game, Mmo and Creative; the keyboard has 82 LEDs for 83 physical keys and encoder press has no LED. Direct caps V at 160, uses ten packets of at most nine LEDs and requires explicit RAM apply. Saved mode 5 maps to Direct for those four profiles and Reactive for the other six.

The RGB research and five-phase implementation guide is [RGB-PLAN.md](RGB-PLAN.md); its Russian counterpart is [ru/RGB-PLAN.md](ru/RGB-PLAN.md). The RGB guide remains the detailed planning source.

## Verification boundary and release gates

Current source build/test results and review findings are recorded in [REVIEW.md](REVIEW.md). Tests, synthetic fixtures and CI establish source/model properties only. They do not establish physical input behavior, settings retention, HID timing, or flash behavior. A positive released packed-image/full-ROM fixture is unavailable because OEM erase-helper bytes are not available; public Intel HEX alone cannot build that image. OEM-private bytes are not added.

Backup capture now reads a complete beta2 snapshot using the existing single HID session. Supported live getters are reconciled with their saved NVM values; the complete NVM, including inactive typed bytes that have no live getter, is retained and repeated for stability. ROM-manifest and storage-status reads are also repeated and checked. Errors and cancellation stop the capture without automatic retry. The snapshot remains in memory until the user explicitly saves a new backup. On Unix, publication uses a private staged directory, validates a reread, avoids replacing an existing target and syncs the parent directory. History scans at most 128 immediate backup directories and 1024 root entries, fully validates candidates, reports skipped invalid folders, and pins a manifest digest for reopen. Restore uses the immutable preview as a guard and executes through a new one-attempt executor. It requires a fresh complete capture equal to the preview target, a verified safety backup, a fresh Esc + left Control hold via the lock/start handshake, and a source re-open immediately before the first setter. Each whitelisted setter is attempted once and checked by acknowledgement, applicable getters and full NVM; macro publication is checked through its published getter. Final full ROM, getters, repeated NVM and manifest are verified. Errors stop without retry or automatic rollback. Restore refuses read-only sessions; stopped RGB is not resumed automatically. Backup inspection now starts restore, supports stop/cancel while retaining the worker, preserves the safety-backup reference after error and offers explicit undo reopening. On success, editor state is reread.

Backup directory operations are implemented for Linux, macOS and Windows. Unix operations are directory anchored; macOS rejects parent ACLs; Windows uses local-drive handle-relative operations without reparse points or hard links and a private user/SYSTEM ACL. Files are synced and publication is no-replace. Windows does not promise Unix parent-directory fsync semantics; UNC/device paths are unsupported. Windows GNU and macOS arm64 adapter typechecks passed, not full-app builds or runtime qualification. A separate cooperative per-device guard also protects the helper independently of the GUI single-instance lock; external Vial software does not honor that advisory guard. A positive released packed-image/full-ROM fixture is still unavailable because OEM erase-helper bytes are unavailable; public Intel HEX alone cannot build that image. No positive full-ROM archive fixture or physical keyboard test is claimed. Physical retention and HID timing require qualification. The dedicated unsigned DRAFT candidate workflow and verifier are implemented; no publication was executed. Six-target CI now includes Windows/macOS tests. Exact evidence is recorded in [REVIEW.md](REVIEW.md). The successful CI run `40174635838` for `1afd0f1` is historical and does not verify current-source execution on all six targets. Current Ubuntu 24.04 source-build evidence does not establish Debian 12 compatibility from a prior binary, nor Windows/macOS/arm64 runtime support. Six-target execution, installers, signing and per-target runtime/function checks remain release gates.

No full first-release qualification is claimed. No live firmware installation flow is connected; the local checker does not flash. Browser work remains a later stage. Read the [plan](PLAN.md), [desktop guide](DESKTOP.md), and [installation guide](INSTALL.md).

## Firmware file checks and installation boundary

The **Firmware files** window performs local validation only. It requires an exact 51,136-byte prepared payload, a 65,536-byte current snapshot that is either a supported OEM revision or exact supported project image, and a personal 65,536-byte OEM recovery ROM. The snapshot and recovery copy must match in protected regions; the payload must match the selected profile catalog. The result shows payload, snapshot, recovery, expected-ROM and input-binding SHA-256 values, data-block count and loader checksum. The window retains copies of the selected bytes and a check summary while it remains open. These results do not prove that the snapshot came from the currently connected keyboard or authorize a release; any future installer must establish its own fresh device and release checks. A pure bounded loader wire codec exists; no live loader transition, reconnect binding or flash operation is connected. Release/revocation authority, durable install safety and readback transaction, physical qualification and settings outcome remain open. No firmware is flashed by this checker.
