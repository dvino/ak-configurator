# Desktop guide

## Supported beta2 images

The source supports the ten exact packed profile images published for AK820 v0.6.0-beta.2: Main, Game, Mmo, Typing, Code, Pointer, Onehand, Creative, Shortcuts and Multios. Each profile has a schema03 settings contract (0x082003), an exact packed CODE/settings identity and explicit directional transitions. The active beta2 catalog is authoritative. The historical source registry is retained only for three schema02 backup identities; it provides no device aliases or beta1 write path. Unknown, custom, trial and mismatched images are rejected. Linked-window hashes do not substitute for packed CODE identity.

Connect the keyboard and allow the application to verify the complete image and load every required setting before editing. The editor supports six layers, 83 physical keys, and one encoder with both rotation directions and its ordinary matrix press. Per-profile assignment counts, QSIDs and source-specific keycode restrictions apply. Typed editors expose only their declared active records. Every typed module edit reads and validates full NVM before and after the change; unchanged defaults cause no setter. A failed write, timeout or readback mismatch stops the session until an explicit reread.

## Offline projects

Start `ak-configurator --demo-ak820` to work with bundled examples without USB access. Choose one of the ten beta2 profiles in the local-project window. These examples are not settings read from a keyboard. Project format v2 pins the target release, catalog and Intel HEX image. Version 1 beta1 projects are rejected and require deliberate manual migration. Saving/opening a project does not capture or restore keyboard settings or OEM firmware.

The schema03 panels provide eight Tap Dance records, eight Key Overrides records, or the active QMK setting IDs according to each profile contract. Unsupported or inactive storage is not exposed. Dynamic Macro and runtime modes remain firmware features; a key assignment does not emulate their physical behavior on the computer.

## RGB controls

The keyboard has 82 individually addressable LEDs and 83 physical keys; the encoder press has no LED. Brightness is limited to 160. Built-in effects are available according to each profile's contract. Direct palette editing is supported only for Main, Game, Mmo and Creative. The original static palette preset remains format v1. The additional local scene editor uses format v2, supports up to 16 ordered/enabled layers with 82-LED masks, Solid/Gradient/Wave/Breathing/Rain effects, horizontal/vertical axes, opacity and 250–60000 ms periods. It provides a local preview, quiet-hours brightness cap based on local wall-clock time (start inclusive, end exclusive, including overnight intervals), and up to 32 undo/redo draft states. Selection uses click, Ctrl/Cmd-click and Shift-click; drag selection is not implemented. Scene presets are local files. No persistent scheduler daemon or automatic playback start exists.

Live playback uses the existing HID owner and a latest-frame queue of one, with a conservative application cap of 10 frames/s; this is not a hardware-qualified rate. Settings, backup, modal and connection-priority work pause playback and discard pending frames. Resume sends a fresh frame only if the same session remains intact. A UI suspend gap over two seconds stops playback and requires explicit restart. Disconnect, session-generation/profile change or error stops without retry or restore. Each frame checks mode ownership; physical RGB mode, speed or HSV changes stop playback without overwrite. Stop cancels unsent packets and leaves sent colors in volatile keyboard RAM. Explicit Off stops and sends one black frame only when the session remains safely intact. No built-in effect is automatically restored; select one explicitly. The application does not save NVM per frame. The firmware has no palette getter or atomic frame commit, so frames and Direct colors remain volatile. Direct apply sends 82 colors in ten packets of at most nine LEDs, with V capped at 160; saved mode 5 maps to Direct for the four supported profiles and Reactive for the other six. These application behaviors do not establish hardware qualification. See the [RGB guide](RGB-PLAN.md).

## Backups and restore preview

Open **Backups**, choose a local folder, then choose **Read complete snapshot** for a verified beta2 keyboard with no pending edits. Capture uses the existing HID session, reconciles supported live getters with their saved NVM values, retains the complete NVM including inactive typed bytes, and repeats NVM, ROM-manifest and storage-status reads. If any check fails or reading is cancelled, capture stops without retry. The complete snapshot is held in memory; choose **Save new backup** to publish a separate dated folder. Saving uses private staging, rereads and validates the staged files, avoids overwriting an existing folder, and syncs the parent directory on Unix.

The saved-backup list checks only immediate folders, up to 128 backups and 1024 root entries. Each listed backup passed full archive validation; invalid folders are counted and skipped. Selecting an entry reopens it with its listed manifest digest pinned and validates it again. Restore from backup inspection executes the guarded restore flow. The fresh complete device capture must still match the immutable preview target snapshot; a verified safety backup is created first. A fresh Esc + left Control three-second hold starts through the lock/start handshake, and the source backup is re-opened just before the first setter. Each whitelisted setter is attempted once and checked using acknowledgement, applicable getters and full NVM, including the published macro getter. Final actual full ROM, getters, repeated NVM and manifest are checked. Failure or cancellation stops without retry or automatic rollback. Read-only sessions refuse restore. The safety-backup reference remains available after errors for explicit undo/reopen; successful restore rereads the editor. Stopped RGB playback is not automatically resumed.

Reset is a separate action in **Backups**. Read the complete current snapshot, choose **Preview reset to release defaults…**, review the supported changes, then confirm. The reset uses compiled defaults for the current exact image, a fresh matching capture, a verified safety backup and the same fresh physical hold and checked one-attempt executor as restore. It preserves inactive, reserved and inaccessible bytes. Undo uses the retained safety backup; no automatic rollback occurs.

**Delete this backup…** requires a separate permanent-deletion confirmation. The archive is reopened and validated against its displayed manifest digest before known files are removed. This does not delete arbitrary folders recursively. Deletion is irreversible and a filesystem error may leave a partially removed folder; inspect the reported result.

Backup file operations are implemented on Linux, macOS and Windows. Unix paths are directory anchored; macOS rejects parent ACLs. Windows uses local-drive handle-relative operations, rejects reparse points and hard links, applies private user/SYSTEM ACLs, syncs files and publishes without replacement. Windows has no Unix parent-directory fsync promise, and UNC/device paths are unsupported. Isolated Windows GNU and macOS arm64 adapter typechecks passed, but full-app builds and runtime qualification remain open. A cooperative per-device helper guard is independent of the GUI singleton; external Vial does not honor this advisory guard. No positive released full-ROM archive or physical keyboard test is available. The `.entlayout` export remains a partial editor snapshot, not a complete settings or OEM recovery backup. `.ak820project.json` files are offline examples pinned to release/catalog/image identity; RGB palettes and scenes are separate files. None of these formats substitutes for a complete device backup.

## Firmware installation and OEM rollback

Use the separate native installation action for bundled beta2 firmware or an exact prepared payload. The ten public IHX/map sets and compiled defaults are bundled for offline preparation. Select a profile, allow the beta prerelease explicitly, choose an existing safety-backup folder and review the immutable preview. For a first bundled installation from exactly validated OEM firmware, explicitly choose defaults: the fresh device capture provides the private packing bytes locally, so a preexisting ROM file is optional. Project-firmware updates and prepared payload files require a supported personal OEM reference. If a supplied reference is invalid, preparation stops without falling back to another source. A manually selected payload must satisfy the same exact release policy. Unknown/custom images remain blocked. A fresh device read binds the plan to the actual keyboard; the local **Firmware files** checker remains an independent three-file check and does not flash.

Complete settings capture is attempted even with **Start with defaults**. If it fails, continuing requires that explicit defaults choice. Preserving settings requires a valid complete capture and supported exact image/transition checks. Required safety archives and the full-ROM snapshot must be saved and reread before erase. When recovery ownership is recorded, the trusted local recovery-manifest registry must also be synced and reread before erase. A failure stops execution and preserves the paths of safety data already saved. Changing the image/settings invalidates the previous preview. Supported project firmware requires a new Esc + left Control three-second hold; OEM uses a separate explicit start. The native owner enters the loader, binds reconnect to the physical USB port, flashes once, reconnects and checks the full ROM. Cancellation is permitted before erase; ordinary close is blocked while the transaction owns the device. Errors stop without retry, reset or automatic recovery, and firmware/settings results are reported separately.

OEM rollback uses a recorded local recovery folder with a pinned manifest and first-capture ownership evidence. The current unit/port and protected regions must match. A missing usable serial or provenance blocks rollback. A personal ROM file by itself does not establish ownership. Recovery and settings data stay local.

**Check release metadata** performs an explicit network request about the pinned beta2 project release/assets. Known withdrawal/change observations remain blocked, including local payloads; network failure retains the last known state. Offline status may miss a later withdrawal. The current selector does not provide a complete stable/historical release browser or arbitrary custom-build admission.

## OS layout helper

Enable **OS layout indicator** and map EN/RU to Off, On or Slow breathing; Normal releases the override. Preferences stay on the computer independently of keyboard reset/update. Unknown/unmapped layouts and unsupported Wayland compositors release indication rather than assuming English. The volatile FD02 v1 heartbeat uses the verified HID owner without NVM writes. Settings, backups, restore/reset, RGB and installation have priority; an error stops refresh without blind retry. If the transport is lost, firmware expires its lease after 3000 ms nominally.

`ak-configurator --ak820-helper` starts the enabled helper without creating editor windows or a renderer. Opted-in `--minimized`/autostart also enters the helper. **Close interface, keep helper** releases the app, renderer and windows and enters the same background loop; opening AK Configurator again signals that process to recreate the interface under its existing instance lock. Ordinary Close uses the enabled helper; explicit Quit exits. The helper checks exactly one USB candidate and the full image/settings before sending; a faulted endpoint remains blocked until successful enumeration observes disappearance or a different instance token. This implementation still needs platform launch, handoff, layout/HID and resource qualification; source support is not a platform-runtime pass.

## Candidate delivery and evidence

Portable packages are Linux x86_64/arm64 `.tar.gz`, Windows x86_64/arm64 `.zip` and macOS x86_64/arm64 `.app.zip`, with SHA256, provenance, public offline firmware inputs and EN/RU instructions. They include explicit per-user installation/removal scripts and remain unsigned candidates; MSI/DEB/PKG and signing/notarization are separate concerns. See [INSTALL.md](INSTALL.md) for extraction, installation and launch.

The native workflows above are implemented in source. No physical flash, OEM rollback, settings retention or complete six-target runtime qualification is claimed. Public IHX/map and default-settings fixtures do not provide a positive released packed-image/full-ROM fixture without the unavailable OEM erase-helper bytes. Current build/test/review evidence is recorded in [REVIEW.md](REVIEW.md). No fully qualified release or publication is claimed.

## Application updates

Open **About AK Configurator → Application updates** to check releases explicitly. Stable is the default; prereleases require opt-in. A newer release can be downloaded only after its complete six-target index, project origin, platform, size and SHA256 agree. The release is checked again before download; a changed or withdrawn selection stops the operation. The verified archive is saved locally and its path is displayed. Quit the application and helper, then follow the included per-user installation instructions. No installer or keyboard command starts automatically, and helper preferences are preserved.
