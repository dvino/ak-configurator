# Графическая фикстура Windows CI

Сохранённые отчёты нативного smoke-прогона `40538179782` показывают одинаковую ошибку Windows x86_64 и ARM64: `egui_glow requires opengl 2.0+`. Runtime-сценарий не завершился. Это ошибка инициализации renderer на этих hosted runners, а не ошибка клавиатуры.

Кандидат `scripts/run_windows_ci_runtime_smoke.py` предоставляет Mesa llvmpipe только Windows CI smoke. Сохраняются production Glow/WGL renderer, настоящее окно и сценарии трея, офлайн-режим приложения, сроки и блокировки при ошибке. Подготовка загружает закреплённый графический архив; приложение запускается через существующий изолированный harness `--runtime-smoke`. Это не системная песочница сети и устройств.

Сторонняя сборка: [mmozeiko/build-mesa 26.2.5](https://github.com/mmozeiko/build-mesa/releases/tag/26.2.5), исходный commit `cb4cc458eff7c4b4b31d2623edd954d66201b88f`. Это не официальный бинарный выпуск Mesa. [Скрипт сборки](https://github.com/mmozeiko/build-mesa/blob/cb4cc458eff7c4b4b31d2623edd954d66201b88f/build.cmd) выбирает нативные LLVM targets AArch64/X86 и статические зависимости. [Документация Mesa](https://docs.mesa3d.org/drivers/llvmpipe.html) описывает размещение Windows WGL DLL рядом с программой.

| Нативная цель | Release asset | SHA-256 |
| --- | --- | --- |
| ARM64 | `mesa-llvmpipe-arm64-26.2.5.7z` | `e7df75398d50e07a68bbffa5cff2ece4c85e5f8ef8bda497f560dd04fe60cbbd` |
| x86_64 | `mesa-llvmpipe-x64-26.2.5.7z` | `d1b713ca2a7fba47a50c058099f13c435ddb76a16a422c334e4d787f9755a31d` |

Хеши обоих загруженных архивов проверены локально. В корне каждого находятся `opengl32.dll`, `libEGL.dll`, `libGLESv1_CM.dll`, `libGLESv2.dll` и три EGL/GLES import libraries. Через stdout 7-Zip в фиксированный файл записывается только точный корневой элемент `opengl32.dll`; путь из архива не определяет место записи. Размер загрузки и DLL ограничен, PE machine type должен соответствовать нативному хосту. Поток чтения ограничивает вывод 128 МиБ, а основной поток задаёт срок извлечения 30 секунд, включая зависание дочернего процесса до EOF stdout. При таймауте процесс завершается и ожидается до очистки.

Отдельный временный каталог внутри `RUNNER_TEMP` содержит архив, DLL и копию production executable. SHA-256 оригинала, копии и smoke-отчёта должны совпасть. Каталог удаляется после успеха и ошибки; пути пакета не изменяются. Отчёт добавляет URL/хеш архива, исходный commit, хеш DLL, хеши executable и область CI-only software graphics. Запрошенный драйвер Mesa обозначается отдельно от production renderer приложения. Он явно не подтверждает независимую проверку реально загруженной процессом DLL. При ошибке сохраняется отдельный диагностический артефакт; упаковка и загрузка кандидатов требуют успеха.

Локальные тесты проверяют pins, некорректные и изменённые входы, несовпадение архитектуры, точный выбор элемента, пределы размера, изоляцию, очистку и сохранение ошибки smoke. Настоящий спящий дочерний процесс проверяет таймаут, завершение, сохранение отчёта ошибки и очистку временного каталога без запуска приложения. Windows они не запускают. Независимое ревью обнаружило, что зависшее извлечение могло обойти таймаут; исправление и тест повторно проверены, замечаний не осталось. Локально прошли десять тестов фикстуры и два теста workflow. Остаётся проверка итоговых исходников. Успех программного renderer не подтверждает аппаратный GPU, физический щелчок трея, совместимость обычных desktop-драйверов или клавиатуру. DLL не входит в пакеты приложения.

В последующем [прогоне 40542473368](https://github.com/dvino/ak-configurator/actions/runs/40542473368) нативные Windows x86_64 и ARM64 smoke прошли с этой фикстурой, а проверки установки, обновления и удаления кандидата также прошли. Оба скачанных архива кандидатов совпали со своими SHA-256 файлами; хеш executable в каждом runtime-отчёте совпал с манифестом и отчётом установки. Проверялся PR head `8554acd`, объединённый в CI как `5f2bea19f4cac2479223119e57a393d24832576e`; последующим коммитам нужен собственный прогон CI. Отчёт фиксирует запрошенный программный драйвер, но независимо не подтверждает, какую DLL загрузил процесс.
