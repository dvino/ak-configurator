# Адаптация десктопной версии и ревью

## Исправления хэндофф, трей и первая реализация MCP — 2026-10-27

База: `fb4fb7b50c89d8fb99ed5e5cdac34aa3459ac4d7`, ветка `desktop-dev`. Переданный бандл `docs/mcp-integration-plan` объединён после независимого ревью документации до реализации. Версия приложения остаётся `0.1.0-alpha.1`; прошивка и точные идентичности десяти профилей beta.3 не меняются. Это неопубликованный бандл исходников, не альфа-релиз. Реализованная версия описана в [MCP.md](MCP.md). Раздел только о плане ниже является историческим.

### Изменения и независимое ревью

- Callback Windows-трея копирует адресата и освобождает mutex до вызовов нативного окна/egui. Убран возможный путь взаимной блокировки при повторном входе; исходное зависание Windows на этом Linux-host не воспроизводилось.
- Временное владение HID OS-индикатором больше не скрывает/сбрасывает подраздел RGB-сцен. Целевой опрос раскладки — 100 мс, проверка завершения задачи — 20 мс, обновление неизменившегося активного override — раз в секунду. Прежний пятисекундный цикл скрытого окна мог превышать трёхсекундный срок прошивки. Опрос без отправки не сдвигает обновление и не повторяет неизменившиеся режимы. Физическая задержка ещё не измерена.
- Последующее сообщение о мигании всего интерфейса связано с передачей HID на каждый опрос, даже без записи. Опрос и запись разделены. При неизменном режиме HID остаётся в UI; необходимые переходы/обновления сохраняют страницы, блокируя ввод. Снимок для отрисовки проверяет идентичность, выбранное устройство и поколение соединения. Ревью обнаружило слишком широкую подстановку возможностей RGB; исправленный снимок сохраняет действительную поддержку Direct, что проверяется для Main/Typing и устаревшего поколения.
- Auto Shift показывал унаследованные переключатели неподдерживаемого QSID 3 при наличии задержки QSID 4. Точный [исходник настроек beta.3](https://github.com/dvino/ak820/blob/88d190abb156960915a0f1f8ac7f602bb401eab3/qmk-8051-ak820/keyboards/ajazz/ak820/ak820_settings.c) отклоняет QSID 3; [компактная реализация](https://github.com/dvino/ak820/blob/88d190abb156960915a0f1f8ac7f602bb401eab3/qmk-8051-ak820/keyboards/ajazz/ak820/ak820_autoshift.c) использует назначенные клавише действия включения/выключения/переключения. Страница предоставляет только объявленные настройки; задержка Main/Typing меняется без несуществующего флага включения. В других поддерживаемых прошивках изменение одного флага сохраняет остальные биты и проверяет чтение; ошибка останавливает редактирование до повторного чтения. Изменение прошивки или физическое включение/выключение не заявляется.
- При видимом запуске предоставленный логотип рисуется до полной инициализации редактора; начальное перечисление HID перенесено из конструктора GUI в существующий фоновый поиск. Замеры разделяют создание окна, заставку, инициализацию и первый кадр редактора. Независимое ревью обнаружило и закрыло ожидание невидимой заставки при свёрнутом запуске Windows. Нативный просмотр также выявил первый кадр редактора со старыми цветами и отсутствующими значками. Тема теперь применяется до создания корневого UI, а запуск ждёт следующего кадра с готовыми шрифтами и стилем. Исправленные нативные кадры и целевые тесты прошли. README на обоих языках использует точный предоставленный файл. Чтение диска до окна, инициализация графики и загрузка процесса ОС остаются за пределами отложенной инициализации.
- Linux использует уже имеющийся zbus для StatusNotifierItem и dbusmenu Показать/Выйти. Без host окно не скрывается; ограниченный фоновый монитор запрашивает восстановление при потере watcher/host. macOS тоже отказывается скрывать окно при неудаче создания трея. Независимое ревью потребовало стандартные групповые методы меню и ограниченные вызовы фикстуры; они добавлены и пройдены через D-Bus. Реальные щелчки мышью и отрисовка панели проверяются отдельно.
- Управление индикатором перенесено в настройки приложения. Избыточное действие закрытия интерфейса удалено. Обычное закрытие следует настройке трея; явный выход из основного меню, трея или Ctrl+Q/Cmd+Q сохраняет проверки unlock/установки и ожидающих записей, отменяет передачу фоновому помощнику. Справка EN/RU обновлена.
- Офлайн-GUI получает новые временные настройки до запуска служб и отвергает смешанные режимы. Проверенные входы HID/перечисления, автозапуска, поиска окон/хуков, обновлений, захвата/моста, установщика и интеграции закрыты. Прежняя изоляция тестового хранилища сохранена. Независимое ревью закрыло пять пропущенных рабочих путей. Намеренные loopback и подставные дочерние процессы сохранены; унаследованный явный запуск настроек приватности macOS не входит в автоматический smoke. Это не универсальная системная песочница.
- MCP использует закреплённый официальный rmcp 3.8.0, отдельную feature `mcp` и только для разработки `mcp-mock`, закрытые DTO и ограниченный рабочий поток устройства. Инициализация распознаёт точный CODE через FD00 до FD01/обычных getter-команд и не загружает настройки. Шесть инструментов предоставляют диагностику, синтетические проверки, жизненный цикл операции и ограниченные metadata-трассы. Замечания о глобальной политике mock, чужой отмене, публикации конечного состояния, классификации ошибок, истечении тихой трассы и устаревшем lease закрыты. Стандартная отмена отсоединяет ответ; отмена операции и EOF управляют кооперативной отменой потока.

Независимые проверки одобрили рассмотренную изоляцию и частичный MCP с контрактом подпроцесса. После исправления меню ревью трея/UI не нашло блокеров исходников, потребовав результат исполнения до интеграции. Успешный Linux runtime ниже закрывает это локальное условие. Windows/macOS, arm64, Wayland, живое владение/отмена помощника и физические ввод/LED/сохранение остаются открытыми.

### Ограничения выпуска и MCP

Workflow кандидата теперь запускает настоящий GUI/tray smoke для всех шести целей Linux/Windows/macOS; verifier требует отчёт с совпадающими платформой, версией и хешем файла. Linux CI использует отдельную D-Bus-фикстуру host. Настройка workflow не означает, что его новые Windows/macOS-задачи уже выполнялись. Пользователь требует Windows/Linux runtime до альфы; релиз, тег, push, установка или команды оборудованию здесь не выполнялись.

Базовый агентный диагностический путь работает в проверенном Linux-подпроцессе. Весь P0 остаётся частичным: не закрыты положительная фикстура полного упакованного CODE, расширенная приёмка replay/отчётов и живые проверки helper/lease. Синтетический FD01 не заменяет успешную полную инициализацию. MCP не управляет существующим GUI, не меняет настройки, не создаёт/восстанавливает копии и не прошивает устройство. P1/P2 не начаты; жизненный цикл UI проверяет отдельный нативный runner. Отчёты/трассы ограничены и живут в процессе. `protocol.smoke` явно пропускает физическое поведение.

документации не запускались сборки, тесты приложения или операции с устройством.

Независимые проверки архитектуры/исходников и протокола прошивки не выявили
архитектурного блокера. Замечания внесены в план:

- Проверка подпроцесса с mock в сборке для разработки отделена от проверки
  поставляемых артефактов; выпускная сборка должна отклонять mock/replay.
- Явный допуск к закрытым данным распространяется на все таблицы действий,
  значения отчётов и сравнений. Определены DTO макросов, Tap Dance и Key Override
  и условие фиксации схем.
- Разделена отмена до перехода в загрузчик, после перехода до стирания и после
  начала стирания. Результат прошивки `NotAttempted` не означает сохранения
  обычной работы клавиатуры; автоматическая команда Restart не добавляется.
- Наблюдение матрицы требует подтверждённой разблокировки и негативных fixtures
  для блокировки/её возврата; неизменённый ответ не доказывает отпускание клавиш.
- Сохранены три попытки согласованного чтения Direct (два повторных начала при
  смене поколения); ошибки транспорта и запись с неизвестным результатом
  останавливают работу без повтора.
- При сверке языковых версий уточнены утрата разблокировки, требование чистого
  хранилища для компенсации, область переходов beta.3, исключение fuzzing на
  реальном устройстве, закреплённые входы сценариев, Cargo `--locked` и сокрытие
  конфиденциальных данных. Переведён оставшийся абзац об альтернативных SDK.

Проверены синтаксис 14 примеров JSON/TOML, совпадение 16 блоков кода между языками,
58 определений ссылок на источники и соответствующие пути/номера строк в
зафиксированных репозиториях, локальные ссылки, столбцы Markdown-таблиц и

### Замечания и исправления

- Применение базовой палитры использует существующий асинхронный поток кадров
  RGB. Чтение и запись палитры Direct v1 проверяют отмену перед каждым пакетом.

До стирания проверяются свежий полный исходный образ, допуск выпуска, подготовленные настройки и долговечный защитный снимок; требуется соответствующее источнику новое подтверждение. Владение физическим портом сохраняется при переходах загрузчика, после переподключения сравнивается полный ROM. Отмена заканчивается на границе стирания. Результаты прошивки и настроек разделены; пути сохранённых копий остаются доступны при ошибке и потере обработчика. Значения по умолчанию выбираются явно, а сохранение/миграция должны точно совпадать с NVM, полученной из проверенного источника. Первая установка встроенного профиля поверх OEM может использовать точный свежий OEM-снимок локально; обновление проектной прошивки и подготовленный payload по-прежнему требуют поддерживаемый личный OEM reference. Неверный выбранный reference не заменяется автоматически другим источником.

Возврат OEM требует локально записанный манифест первого снимка и совпадающую привязку непустого serial/USB-порта. Запись публикуется атомарно, синхронизируется и перечитывается до стирания; обычное сохранение настроек сохраняет записи, добавленные обработчиком. Без доказательства принадлежности откат блокируется. В просмотр копий добавлены сброс к настройкам выпуска через защищённый исполнитель восстановления и отдельно подтверждаемое удаление только проверенных файлов архива с закреплённым digest. Сброс сохраняет неактивные/резервные байты. Ошибка файловой системы может оставить частично удалённую копию; она сообщается без рекурсивного удаления и повтора.

Необязательный помощник FD02 сопоставляет EN/RU обычную индикацию, выключение, включение и дыхание, отправляет ограниченные временные подтверждения связи и уступает единственного владельца HID другим операциям. Неизвестная раскладка снимает переопределение; ошибка блокирует продолжение до нового конкретного сеанса. `--ak820-helper` и разрешённый свёрнутый автозапуск не создают GUI. Обычное закрытие освобождает приложение/renderer и оставляет помощник; повторный запуск создаёт GUI в том же процессе, явный выход завершает приложение. Глобальные обработчики трея Windows/macOS обращаются к текущему GUI через освобождаемый посредник и не удерживают закрытые Context/HWND. Обновления приложения теперь относятся к AK Configurator и запускаются пользователем. Переносимые кандидаты используют Linux `.tar.gz`, Windows `.zip` и macOS `.app.zip`; workflow проверяет и сохраняет все шесть артефактов без публикации выпуска.

### Замечания независимого ревью и исправления

Независимые рецензенты проверили код, ссылки на прошивку, согласованные документы EN/RU и записанные свидетельства. Исправлены следующие случаи:

- Сохранение настроек подготовленного файла доверяло digest самого выбранного файла. Теперь UI и исполнитель требуют независимо полученные байты настроек источника/цели; добавлены регрессии неверного размера и несовпадения.
- Новая блокировка выпуска могла оставлять старый план исполнимым. Ожидающая проверка запрещает запуск, блокировка закрывает предпросмотр, а исполнение требует нового допуска. Доказанная смена выпуска не теряется, даже если у другого API-артефакта нет digest.
- Ошибки после сохранения снимка могли скрывать пути копий. Ссылки на настройки и ROM сохраняются при всех исходах. Принадлежность первой OEM-копии записывается синхронно и долговечно до стирания; устаревшие настройки GUI не могут удалить её pin.
- SDCC обрезает некоторые длинные неиспользуемые имена в map. Эти совпадения больше не отклоняют десять публичных map; все символы, которые использует упаковщик, должны оставаться однозначными. NVM по умолчанию всех десяти профилей совпадает с независимо полученными публичными эталонными суммами.
- Первая OEM-установка необоснованно требовала заранее сохранённый дамп. Встроенный запрос теперь принимает только точный свежий проверенный OEM-снимок; проектные источники и неверные выбранные файлы по-прежнему отклоняются.
- Предложенная очистка трея использовала `set_event_handler(None)`, который `OnceCell` закреплённых библиотек не применяет после регистрации. Вместо этого используются однократные обработчики процесса и очищаемый посредник текущего GUI. Исправление прошло изолированную компиляцию Windows/macOS и новое независимое ревью.

## Контролируемое восстановление и интеграция десктопа — 2026-10-26

Эта контрольная точка начинается с `bbd18ef6bfeb86422e7696d69701d3fa43f203f4` в ветке `desktop-dev`. Версия приложения остаётся `0.1.0-beta.2`; цель прошивки — AK820 `v0.6.0-beta.2`. Каталог прошивки, идентичности архивов и версия выпуска не менялись.

Окно резервных копий теперь запускает контролируемое восстановление по неизменяемому плану. До записей исполнитель заново читает полный текущий ROM и требует совпадения точной идентичности образа и всего NVM с целевым снимком предпросмотра, создаёт и проверяет долговечную защитную копию, запрашивает новое удержание Esc + левого Ctrl три секунды через handshake блокировки/старта и повторно открывает исходную копию с закреплённой идентичностью непосредственно перед первой записью. Доступны только разрешённые setter; каждый выполняется один раз и проверяется подтверждением, подходящим getter и полным NVM. Публикация макроса проверяется через опубликованный getter. Итоговая проверка сравнивает фактический полный ROM, getter, повторный NVM и манифест. Ошибка или отмена останавливает операцию без повтора и автоматического отката. Сеанс только для чтения запрещает восстановление. При отмене сохраняется владение worker; после ошибки ссылка на защитную копию остаётся доступной для явного undo/reopen, а после успеха перечитывается состояние редактора. Остановленный RGB автоматически не возобновляется. Кооперативная блокировка устройства независима от блокировки GUI; внешняя программа Vial эту advisory-блокировку не соблюдает. Физическое восстановление и запись на клавиатуру не выполнялись.

Файловые операции резервного копирования реализованы в Linux, macOS и Windows. Unix-операции привязаны к открытым дескрипторам каталогов; macOS отклоняет ACL родительского каталога. Windows использует операции относительно NT handle для локальных дисков, отклоняет reparse point и hard link, задаёт приватный ACL пользователя/SYSTEM, синхронизирует файлы и публикует без замены. В Windows не обещана синхронизация родительского каталога как в Unix; UNC/device paths не поддерживаются. Изолированные typecheck Windows GNU для резервных копий/владения и macOS arm64 для anchored filesystem прошли. Это не полные сборки приложения и не проверка запуска платформ.

## Модели восстановления, образов и каталога копий — 2026-10-25

Следующий пакет подключает `ak820_restore_plan`, `ak820_image_pack`,
`ak820_install_plan`, `ak820_backup_files` и окно просмотра копий из строки
состояния. Запись настроек beta и прошивка не включаются.

Модель восстановления использует точный каталог, миграцию schema02→schema03
и декларативные предусловия каждой записи. Schema01 отклоняется. Упаковщик
совпадает с закреплённым Python-эталоном по хешам постоянного и пробного выхода
на открытых синтетических данных; разделители записей Intel HEX совпадают
с Python. Модель установки сохраняет девять невыполненных аппаратных условий,

только для OEM, отказывает в отмене после стирания без изменения состояния,
