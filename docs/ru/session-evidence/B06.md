# B06 — ограниченный RGB worker

English: [EN](../../session-evidence/B06.md).

## Текущий статус

**Ограниченная офлайн-область RGB worker B06 принята 2026-11-03** независимым reviewer `b06_ui_review` после review EN/RU документации, сообщённых результатов тестов, прямого запуска UI test и указанных source-file hashes. Приёмка охватывает только offline evidence B stage 3. Она не квалифицирует native OS window, физическое устройство, macOS или готовность выпуска, и не подтверждает, что проверенный test binary собран из inventoried source. Общее поведение non-AK820 и Wasm не менялось. B07 началась.

Позднее review B07 выявило недостаточную привязку к фактическому owner в общем RGB admission/drain/completion path. Принятый checkpoint B06 эту корректировку не проверял; узкий owner-query fix и zero-packet cases для RGB выполняются в рамках B07 и не входят задним числом в эту приёмку.

Readiness audit обнаружил, что нужные проверки уже существуют и должны переиспользоваться: `src/hid_ak820.rs` уже применяет FD01 guard до и после операции, а `ak820_verify_write` обеспечивает существующий SET/GET, SAVE/GET и NVM readback. Не добавлять дублирующий GET или второй engine.

UI worker может отменить действие до вызова метода; после начала метода выход из UI worker не останавливает внутренние transport packets. Узкий cancellation hook внутри существующего transport/guard разрешён, чтобы при выходе предотвращать отправку ещё не пересечённых границ операции packets. Сохранять ровно один SET и не более одного SAVE по действующей policy на одну submitted logical operation. Оставлять предусмотренные verification/status packets, кроме случая, когда cancellation или exit произошёл до их границы; тогда прекратить дальнейшую отправку и вернуть fail-stop uncertain result. Не повторять, не воспроизводить и не продолжать submitted operation незаметно после выхода.

Во время submitted operation отключать RGB controls. Ограничить очередь одной submitted command и одним заменяемым unsent draft; объединять можно только unsent draft. Exit остаётся неблокирующим, с ограниченным ожиданием in-flight работы и без последующих packets или draft. Authorization guard и beta.5 write denial не меняются. Физическая квалификация H02 проводится отдельно и остаётся pending.

Первый RGB test run с default features выявил проблему порядка transport-проверок в SAVE/GET fault fixture: Vial RGB GET echo в packet 7 (`[8, 0x41]`) проверялся только после следующего NVM readback packet 8. Этот GET echo отличается от FD01 pre/post status checks. Код изменён: GET echo проверяется до NVM readback; mismatch значения при корректном header по прежней policy всё равно доходит до packet 8. Это не guard по счётчику packets. Второй snapshot тестов прошёл после этого изменения, но до исправления close handling ниже.

Независимый UI review также выявил exact returned-image checks, raw/private error text, flush при Quit до cancellation и deferred writes после выхода. Автор добавил exact returned-image checks и bounded EN/RU messages. Позднее review обнаружил, что обычные close actions (tray, Ask/cancel и unlock) ошибочно включали постоянный RGB exit/poll-only режим. Исправление включает этот режим только при подтверждённых Close/Quit и helper handoff; обычные tray, Ask/cancel, unlock и прежнее non-RGB поведение сохранены. Последний UI review не обнаружил blocker: committed exit не перенимает handle; headless native-host UI model использует exit-first guard/logic и poll-on-exit; close-pass feedback передаётся. Тесты покрывают same-generation swaps, bounded repeated reads после mismatch и stale generation с сохранением более нового status/recovery. Отдельный Quit-request test выполняется не менее 5,1 s при background updates каждый frame; до и после completion packets не отправляются, несвязанный QMK draft остаётся unsent. Отдельный headless native-host test dispatch-ит application window-close event. Эти тесты не проверяют native OS window, window manager или реальный HID.
