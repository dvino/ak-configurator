# C03 — общий проверенный инструмент резервного копирования: ограниченная офлайн-область принята, 2026-11-03

Английская версия: [EN](../../session-evidence/C03.md).

## Результат

Адаптер C03 добавил `ak820_backup` как седьмой инструмент MCP. Он повторно использует существующую сверку резервной копии и частное хранилище C02. MCP возвращает метаданные копии и идентификатор артефакта, но не байты ROM или настроек. Инструменты записи не добавлены. Независимый review `c03_backup_review` принял ограниченную офлайн-область C03 без блокеров.

## Записанные проверки

- `cargo test --locked --bin ak-configurator --features mcp-mock mcp_backup -- --test-threads=1`: 8 пройдено, 3 пропущено, 1 986 отфильтровано; 1,45 с.
- Для явно указанного нового mock-exe с `AK820_C01_PERMANENT_PATH` и `AK820_C03_FULL_ROM_PATH`: `mcp_backup --ignored --test-threads=1`: 3 пройдено, 1 994 отфильтровано; 2,95 с. Использованы частные host-fixture и автономная модель полной ROM, а не установленная клавиатура или устройство.
- Группа регрессии native backup: 38 пройдено, 1 927 отфильтровано; 5,66 с.
- `cargo fmt --check` и строгие `LINT-N`/`LINT-C`: успешно после исправления псевдонима сложного типа тестового кортежа. Mock-сборка: успешно, 45,53 с, ноль предупреждений, incremental, два задания. Target: `D:\codex-ak-configurator-c02-target`.
- SHA256 C03 mock-exe: `332689c5c1ad11199ac1903922621d239f1bc5d1c148adaeb38fb3290445a921`. SHA256 отдельного production-exe: `5281291e873b4103d8e3a9febc23a81323c0d45f5154901519736660e3f2d7bb`. Это разные артефакты; хеши inventory сами по себе не аттестуют связь исходников с бинарными файлами.
- `python scripts/test_mcp_stdio.py --binary <mock>`: успешно для протоколов `2025-11-25` и `2026-07-28`; только метаданные; вызовов HID enumeration не было.
- Объединённый mock/production STDIO: `python scripts/test_mcp_stdio.py --binary <c03mock> --production-binary <c03production>`: exit 0 для обеих версий протокола. Production metadata tools прошли; доступ к mock-backend был ожидаемо отклонён. Вызовов оборудования не было.
- `npm ci --offline --ignore-scripts --prefix scripts/mcp-interop` и `node scripts/mcp-interop/check.mjs --binary <mock>`: успешно. Node 22.23.2, npm 10.9.8; установлено 197 пакетов, проверено 198, уязвимостей 0; SHA256 lock-файла `61925e541ea1662ebabde98d8dae42115d421e45423ecbe5fb6f34cf03e7ff9d`. SDK handshake/schema и проверки fixture/status прошли; согласованная версия протокола — `2025-11-25`. Inspector discovery и `tools/list` вернули по семь инструментов; ошибок схемы 0 и 50 предупреждений переносимости `uint64` для семи схем.

Модель частной полной ROM-fixture проверила OEM backup, защищённые области, точное наложение payload официальной beta.5 schema 03 в диапазоне `0x2800..0xefc0`, хеши, boot marker и journal. Хеши входных данных локальной проверки: полная ROM, 65 536 байт — `abdb30dedac76e3221024cb901e92e36c2d2ebfffd8985b6685486fc0c15a260`; permanent image, 51 136 байт — `037c394278fa1ce3352aaa5828292b63022a5804385e06d0363ead117efa73bf`; CODE — `cd11665942abb5dc01b3bdce0c73b1520c6e106a9cb8d754b891b12171e4f784`. Эти значения идентифицируют только локальные входы проверки; raw ROM и частные пути здесь не приводятся.

Три группы fixture покрывают точный пятифайловый native-контейнер; отмену bootstrap, отключение и FD01 storage fault; а также full-engine capture, изоляцию контейнера, совпадение с native files, несовпадение QS23, отключение, отмену и искусственный сбой store до открытия при пустом inventory. Storage fault введён тестом и не подтверждает поведение при реальном заполнении диска. Проверка границы публикации использует кэшированную модель без отмены; это не гонка параллельных `store.put`. Нижнеуровневые тесты отказов C02 являются отдельным свидетельством.

## Проверка и ограничения

Независимый review `c03_backup_review` принял ограниченную офлайн-область после статической проверки исходников/документации и независимой сверки 71 хеша source inventory, агрегата и хеша отчёта. Проверяющий принял сообщённые тесты, сборки, STDIO и SDK/Inspector без повторного запуска. Инвентарь: [B08-C03-SOURCE.json](B08-C03-SOURCE.json), SHA256 `14759d3b14f72a20cb7b49de998604e22ecfc000356e953547366e8a97e24351`; digest отчёта `a36e866d721b890e86510f3b04ae6c638681ee9b838c8475afaf9b4b76c7bdc8`. Review не аттестует связь исходников с бинарным файлом или полноту inventory. Production-сборка завершилась за 4 мин 43 с с exit 0 (`cargo build --locked --bin ak-configurator --features mcp`, 317 crates, debug info disabled, два задания, `RUSTFLAGS=-C debuginfo=0`).

В отчёте C02 Windows сообщает `DirectoryFlushUnsupported`; ограничение долговечности сохранено. Используются общие lease устройства, ошибки и read-only session. Diagnostic capture разрешён только после точного bootstrap C01 для beta.3/beta.5. Архив использует общий manifest и версионный lossless-контейнер с тем же строгим валидатором. Ответ содержит только метаданные и ID артефакта. Запись настроек beta.5 остаётся запрещена. Второго HID engine, writer настроек, инструмента prepare или execute нет. C04 добавит prepare только после B11. macOS не квалифицирована; H01 ожидает выполнения.

**Состояние доказательств:** сообщённые source/tests/mock/stdio/SDK и production build/combined STDIO прошли; независимый review принял ограниченную офлайн-область без повторного запуска сообщённых результатов. Поведение устройства и связь исходников с бинарным файлом не установлены. **Итог: ограниченная офлайн-область принята.** Следующая карточка — C04 после выполнения зависимости B11.
