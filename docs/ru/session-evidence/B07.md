# B07 — конечная unlock operation

English: [EN](../../session-evidence/B07.md).

## Текущий статус

**Ограниченная офлайн-область принята (2026-11-03).** Независимый reviewer `b07_session_review` принял frozen source/host checkpoint B07 после независимого сопоставления report SHA256 B07-SOURCE и hashes всех 64 указанных source files. Результаты тестов и lint приняты по сообщённым данным, без повторных запусков reviewer. Приёмка охватывает только офлайн-область finite unlock и shared logical owner binding, описанную здесь. Она не подтверждает source-to-binary linkage, физический USB descriptor, native window, физический ввод/устройство, macOS, parent-death/helper lifetime Q02 или готовность выпуска. Live unlock H03 остаётся отдельно gated. Ранее принятый checkpoint B06 не охватывал эту позднюю общую owner-binding корректировку.

До B07 polling unlock status зависел от UI repaint, а ошибки могли запускать retry. Текущий B07 worker использует одну общую session и наблюдает каждые 200 ms независимо от UI frames. Denial, error и disconnect являются terminal и не запускают автоматические polling/retry. Уже подтверждённое состояние unlocked завершается успехом сразу.

Для нового запуска 15-секундный срок dispatch начинается только после подтверждения FE06. Уже выполняющуюся операцию нельзя запускать повторно через START; после initial status для неё предусмотрено отдельное 15-секундное окно наблюдения. FE07 может отправить подтверждение FE05, поэтому cancellation и committed exit проверяются на каждой границе packet. Срок ограничивает dispatch. Virtual tests проверяют timing dispatch; caller budget Windows packets составляет 4 секунды для USB и 8 секунд для BLE. Сквозной хвост scheduling/reaper не измерен, поэтому жёсткая гарантия завершения за 15 секунд не заявляется.

Обычные non-AK USB FE05/06/07 helpers сейчас следуют transport retry policy; узко разрешённое изменение — одна попытка. Первый transport-only вариант добавил однократный dispatch и guarded polling callback, затем работа перешла к общему конечному worker. AK820 и BLE уже используют одну попытку. Generic non-AK820/Wasm поведение не меняется, кроме этого ограничения попыток. Переиспользовать guarded exit lifecycle B06, при необходимости переименовав RGB-specific field. После committed exit новые packets запрещены; завершение host-side ожидания не отменяет работу firmware. Beta.5 write denial и свежий installer confirmation flow с Esc+left Control остаются без изменений.

Windows path использует существующий `HidProxy`. Его caller budget на packet составляет 4 секунды для USB и 8 секунд для BLE и охватывает очередь, запись и чтение. 15-секундный unlock deadline прекращает новый dispatch; сквозной хвост scheduling/reaper не измерен. Это не жёсткая real-time или сквозная гарантия завершения за 15 секунд. Один локальный read timeout 500 ms сам по себе не ограничил бы write, зависший внутри child process; существующий proxy изолирует такой transport-вызов. Этот audit относится к Windows и не подтверждает физическое runtime-поведение Linux.

Timing tests используют фактический worker и shared fake HID delays (5 секунд для initial status и 8 секунд для START), timestamped polling каждые 200 ms (74 наблюдения) и FE06 deadline origin; physical sleep, keypress или HID не используются. Progress test намеренно публикует 3, затем 5, не сбрасывая исходный deadline. При admission и completion выбранный logical target сравнивается с сохранённым `ProxySlot.device`; при открытии helper один раз проверяет actual target claim. Это не измерение физического descriptor на каждом packet. `TestHid.boundDevice` по умолчанию `None` и завершается fail-closed; обхода missing owner в тестах нет. Wrong-owner и missing-selection tests проверяют ноль packets для RGB и unlock. Identity metadata Windows GUI proxy является authoritative; неподдержанные Local/BLE пути без доказательства owner должны закрываться fail-closed. Не добавлять второй engine и не ослаблять known-image/source policy. Принятый исторический checkpoint B06 не охватывал это позднее исправление общего path.

USB transport timeout должен отличаться от disconnected: сохранять реальную цепочку ошибки приватно, а в UI показывать только bounded labels phase/cause, без raw paths или payload. Это требование к классификации реальной причины, а не синтетическое универсальное сообщение.
