# B08 — стабильность кадров

English: [EN](../../session-evidence/B08.md).

## Текущий статус

**Ограниченный офлайн-объём B08 принят (2026-11-03) независимым review `b08_frame_review`; итоговый review документации закрыт.** Проверяющий закрыл замечания в пределах зафиксированного offline scope. Проверяющий не запускал заявленные тесты и lint повторно. Исходники B08 заморожены в пяти UI-файлах: indicator, status, backup inspection, Vial task и app lifecycle. Реализация принадлежит `b08_frame_stability`. Независимое source review закрыло прежний блокер — отсутствие проверок фактического состояния страницы и диалога — до изменения с прогревом. Усиленный тест проверяет фактический заголовок Main или Backups, prompt пути, заголовок Help, egui window ID и прямоугольник, а перед измерениями требует видимое окно Help. Итоговые результаты tests приведены ниже и приняты без независимого повторного запуска.

Проверка кадров выполняет восемь ограниченных итераций прогрева с продвижением времени, затем наблюдает по 200 кадров отдельно на Main и Backups для каждого сценария: обычного состояния, занятой operation и занятой lease. Последовательность detector (100 постоянных English samples, затем 100 чередующихся English/Russian samples) относится только к обычному состоянию; locale UI остаётся English. В сценариях operation busy и lease busy тест проверяет паузу sampling и отсутствие `Sample` job. Fixture вручную подставляет `Sample` и завершение записи; фактический queued-write path не проходит. Более ранние узкие тесты покрывают реальный dispatch. Frame fixtures не отправляют HID packets.

Первый default запуск прошёл 21 indicator test. Его filtered UI запуск прошёл 218 tests, 2 ignored, 1744 filtered за 70,65 s; эти результаты получены до усиления проверок страницы и диалога. Первый повторный запуск с MCP mock прошёл 20 indicator tests и завершился одной ошибкой, 1974 filtered за 1,07 s: в кадре 0 Help не был виден. Это исторические результаты. После добавления ограниченного прогрева и precondition видимого Help итоговый default запуск indicator прошёл 21 test, 1944 filtered за 6,47 s. Итоговый default UI запуск прошёл 218 tests, 2 ignored, 1745 filtered за 71,81 s. Узкий запуск backup прошёл 38 tests, 1927 filtered за 5,66 s. Форматирование прошло. Первый strict LINT-N сообщил о type complexity у нового кортежа состояния frame-теста; root owner заменил его на `cfg(test) pub(super)` alias `TestFrameState` без allow и изменения поведения, затем успешно повторил N0 и C0. Текущая root mock build для C03 не относится к квалификации B08. Авторство C03 не связано с владением Cargo: авторы C03 Cargo не запускают.

Проверяется видимость недавно добавленного app-version label на общей service panel; это не доказывает отсутствие прежнего flicker. Непрерывность egui window ID и прямоугольника — assertion UI model, она не доказывает непрерывность native window allocation. Путь backup встроен в страницу, это не modal dialog. Эти проверки дают офлайн UI/model evidence, но не квалифицируют native window или физическое устройство.

Пять файлов реализации B08 были заморожены во время production build; эта сборка не является доказательством B08. Текущая root mock build для C03 также не входит в квалификацию B08. Проверки egui window ID/прямоугольника не квалифицируют native window allocation. Общий source inventory подтверждает только записанные hashes, но не полноту списка и не source-to-binary linkage. Пути private checkpoint и настройки не приводятся.

**Итог:** ограниченный offline scope стабильности кадров B08 принят через `b08_frame_review`; проверяющий не запускал заявленные тесты/lint повторно. Это не подтверждает фактический queued-write path, непрерывность native window, поведение физического устройства или H01. Issue #5 ожидает Windows read-only observation; H01 ожидает выполнения.
