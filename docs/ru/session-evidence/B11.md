## Состояние

**Ограниченная офлайн-область B11 принята (2026-11-03) независимым reviewer `b11_independent_review`.** Reviewer закрыл проверку evidence после указанных исправлений. Приёмка относится только к host/model evidence выбора релиза, допуска и сохранения настроек. Для подготовительной MCP input guard отдельно закрыта ограниченная проверка документации/evidence; подготовка C04 не реализована, inventory MCP остаётся из семи инструментов.

`InstallerRelease` поддерживает Beta3, Beta4_1 и Beta5. Beta5 выбирается по умолчанию; prerelease требует явного opt-in и сохранённого осознанного выбора default. Допуск связывает точные pinned release, catalog, matrix, capability, IHX, map и packed CODE. Проверенный набор содержит 200 canonical pairs: Beta4/Beta4_1 → Beta5 и Beta5 → Beta5 reinstall. Beta3, OEM, unknown, ambiguous, downgrade, несовпадение pin и отсутствие prerelease opt-in запрещены. Release-specific sticky withdrawal map сохраняет legacy blocks при смене tag и сетевого состояния.

Identity source candidate/instance отделена от выбранной цели; наблюдённый alias Beta4 отделён от package/receipt provenance. Project source упаковывается существующей classified embedded-payload routine с проверками target, полного ROM и protected areas. Необязательный OEM reference не является восстановлением per-unit. Второго engine нет. Standalone restore и setters beta.5 остаются запрещены; допущенная install pair не даёт права на restore.

## Контракт сохранения

Общее сравнение проверяет logical значения QS, RGB, keycodes и macros на source и target. Записи Tap Dance и Key Override проходят структурную проверку, а ёмкость slots проверяется в обоих images; проверяются Combo actions и slots. Их bytes сохраняются, но это evidence не доказывает отдельную semantic equivalence Tap Dance или Key Override. Ограничения typed-codec и firmware contract остаются. Defaults не подставляются молча. Официальная миграция schema 03 → 03 копирует байты. В pinned C defaults есть реальное различие: uniform all-zero или all-`0xFF` QS beta.4 при defaults beta.5 изменил бы QSID 22 с 0 на 1. Только этот точный диапазон в 24 байта материализуется из старого V2 golden; все остальные bytes сохраняются, а logical значения, проверяемые общим сравнением, остаются равными. Существующая корректная V2 запись остаётся побайтно неизменной. Повреждённые и частично пустые записи отклоняются.

Golden: `5153020f7f002800c80000005000af000100000000008e61`. В pinned source Beta4 commit `7adcfccf265a7a445f84daee420d323eece93c5a` и Beta5 commit `dfd0770f9ef64bf5c7ab6d40e9f9e7b4354cd2cd` используется шаблон C default-array version 2; это не доказывает версию сохранённой записи. Startup beta.5 меняет данные только в RAM до последующего изменения настройки и её commit. Image QS3 и marker 300 beta.5 отделены от stored record. Все опубликованные NVM schemas — `082003`; default `082002` в официальном CLI ошибочен. Миграция official schema 02 → 03 вызывает Python settings-record default VERSION 2. Preview описывает конверсию и показывает производный NVM hash; результат связан hashes source, payload и ожидаемого NVM.

Полные old/new commit, blob и source hashes приведены в [B11-QS-DEFAULTS.json](../../session-evidence/B11-QS-DEFAULTS.json). Это сравнение pinned source, не evidence установленного устройства.
