# Установка и разработка

AK Configurator `0.1.0-alpha.1` — неопубликованный альфа-кандидат. Текущие исходники, проверки исполнения Linux и ограничения других платформ приведены в [статусе](STATUS.md) и [отчёте](REVIEW.md). Workflow подготовил шесть неподписанных нативных пакетов. Все шесть прошли итоговые CI-проверки работы и установки; подпись и публикация остаются открытыми. Исторические результаты Windows/macOS и кросс-компиляции не квалифицируют эти исходники. Встроенные файлы прошивки сверены с опубликованным релизом AK820 beta.3. Браузерная версия последует после нативного этапа.

## Сборка из исходников

Используйте Rust 1.97 и системные зависимости выбранной платформы. В Ubuntu 24.04 установите зависимости Linux, используемые в `desktop-dev`:

```sh
sudo apt-get update
sudo apt-get install -y --no-install-recommends \
  build-essential pkg-config libdbus-1-dev libgtk-3-dev libudev-dev libpulse-dev \
  libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev \
  libxkbcommon-dev libxkbcommon-x11-0 libgl1-mesa-dev zenity
```

Диалоги Save/Open в Linux используют доступный XDG desktop portal или резервный `zenity`. В минимальном окружении рабочего стола или контейнере может не быть ни того, ни другого; установите один из вариантов перед работой с файлами.

Из корня репозитория соберите приложение и последовательно запустите тесты:

```sh
cargo build --release --locked
python3 scripts/build_cava_helper.py --output-dir target/release/audio
cargo test --locked --all-targets -- --test-threads=1
```

Последовательный запуск тестов снижает нестабильность HID-тестов процессов, использующих общий ресурс. Офлайн-предпросмотр интерфейса:

```sh
cargo run --locked -- --demo-ak820
```

Демонстрационный режим не ищет и не открывает HID-устройства. Примеры не являются копиями настроек устройства. Исполняемый файл находится в `target/release/ak-configurator` для Linux/macOS и `target/release/ak-configurator.exe` для Windows. Сборка и host-тесты не подтверждают физическую работу клавиатуры.

Текущие доказательства сборки исходников относятся к Ubuntu 24.04 и Rust 1.97.0. Успешный запуск старого артефакта в Debian 12 не подтверждает совместимость текущей сборки. Alpine/musl не квалифицирован. Для Linux нужны системные графические библиотеки и portal или Zenity для диалогов файлов.

### Встроенный музыкальный компонент

Полный пакет кандидата содержит `audio/cava` (`audio/cava.exe` в Windows) рядом с приложением; в macOS он находится в `Contents/MacOS/audio`. Каталог нужно сохранять рядом с бинарником. Установщик для пользователя копирует его автоматически. Для музыки не требуется отдельная установка OpenRGB или CAVA. В пакет также входят точные архивы сторонних исходников и уведомления; при распространении их необходимо сохранять.

Команда выше собирает закреплённый CAVA и статические FFTW/iniparser. Для Linux дополнительно нужны клиентская библиотека PulseAudio (`libpulse0`) и работающий PulseAudio либо PipeWire-Pulse. При разработке через `cargo run` используйте `--output-dir target/debug/audio`. Windows-компонент собирается CMake/MSVC с закреплённым манифестом vcpkg и статическими зависимостями; задайте `VCPKG_ROOT` для его checkout. В macOS нужны инструменты командной строки Xcode и SDK 14.2+ для звукового компонента. Системный захват macOS требует 14.2+ и согласия пользователя; остальные функции приложения имеют отдельные требования. См. [THIRD-PARTY-AUDIO.md](THIRD-PARTY-AUDIO.md).

## Доступ к устройству в Linux

Если Linux запрещает доступ к HID, явно установите правило udev AK820 из корня репозитория:

```sh
sh linux/udev/install-vial-rules.sh
```

При необходимости скрипт запросит повышение прав через `pkexec` или `sudo` и запишет `/etc/udev/rules.d/59-ak820.rules`. Правило ограничено USB-идентификаторами AK820. Это необязательное изменение системы; сборка и демонстрационный режим его не выполняют.

## Поддерживаемое устройство и пакеты

Контракт beta.3 в исходниках поддерживает десять точных упакованных образов профилей v0.6.0-beta.3: Main, Game, Mmo, Typing, Code, Pointer, Onehand, Creative, Shortcuts и Multios. Перед разрешением редактирования приложение проверяет идентичность упакованных CODE/настроек и обязательные настройки. Неизвестные, пользовательские, пробные и несовпадающие образы отклоняются. См. [руководство по десктопной версии](DESKTOP.md). Окно «Файлы прошивки» проверяет локальные байты и не прошивает устройство. Встроенный каталог beta.3 содержит `flashing_authorized=false` и не содержит привязок разрешённых образов, поэтому установка beta.3 сейчас заблокирована даже с opt-in и точной проверкой идентичности. Beta.4.1 выбрана по умолчанию для прошивки точных образов beta.4 по закреплённым каталогу релиза, матрице прошивки и хешам упакованного CODE; beta.3 остаётся альтернативой. Beta.4.1 не подтверждает проверку оборудования и не разрешает запись сохранённых настроек или восстановление. Все десять beta.3 IHX/settings identities совпадают с проверенными кандидатами, хеши карт — с матрицей релиза, а метаданные approved-release закрепляют все десять образов за точным installer release. Это подтверждает идентичность входных данных релиза, но не поведение устройства. Переход в загрузчик и переподключение привязаны к USB-порту; долговечные защитные данные сохраняются и перечитываются; выполняется одна попытка с проверкой полного ROM и раздельными результатами прошивки/настроек. Свежий install-only/OEM владелец без загруженных настроек проекта может пропустить неподдерживаемое чтение настроек, но обязан пройти точные проверки полного ROM и защитных данных. После начала чтения настроек любая ошибка останавливает подготовку, даже при defaults или rollback. Для разрешённого обновления точно классифицированный образ проекта может предоставить проверенные байты восстановления без старой личной OEM-копии; это не создаёт и не заменяет личный архив восстановления OEM. Предоставленный личный OEM reference должен быть поддерживаемым и действительным; при неверном reference fallback не применяется. Обязательные защитные данные и сохранённое доверие к манифесту восстановления синхронизируются и перечитываются до стирания; ошибка останавливает поток с сохранением записанных путей. Это реализация исходников: физическая прошивка, сохранение и возврат OEM не квалифицированы.

Workflow `desktop-dev` задаёт исполняемые файлы разработки для Linux и Windows x86_64/arm64 и macOS x86_64/arm64. Каждый артефакт содержит исполняемый файл и `SHA256SUMS`; это неподписанные сборки разработки, а не установщики. Итоговый нативный workflow для текущих исходников `b3ecae1` завершился успешно; исторические артефакты не являются текущими пакетами alpha.1. Известный успешный запуск шести платформ на коммите `1afd0f1` исторический и не подтверждает текущие исходники alpha.1.

Выберите подходящий артефакт: `development-binary-linux-x86_64`, `development-binary-linux-arm64`, `development-binary-windows-x86_64`, `development-binary-windows-arm64`, `development-binary-macos-arm64` или `development-binary-macos-x86_64`. Скачайте ZIP из успешного текущего запуска и распакуйте. Перед запуском сверьте исполняемый файл с `SHA256SUMS`. В Linux выполните `sha256sum -c SHA256SUMS`, затем `chmod +x ak-configurator && ./ak-configurator`. В macOS выполните `shasum -a 256 -c SHA256SUMS`, затем `chmod +x ak-configurator` и `./ak-configurator`. В Windows PowerShell сравните `(Get-FileHash .\ak-configurator.exe -Algorithm SHA256).Hash.ToLowerInvariant()` со строкой в `SHA256SUMS`, затем запустите `Start-Process .\ak-configurator.exe`.

## Пакеты-кандидаты для десктопа

Запуск `desktop-dev` также загружает отдельный артефакт `desktop-candidate-${platform}` для каждой из шести платформ. Для Linux это архив `.tar.gz`, для macOS — архив приложения `.app.zip`, для Windows — переносимый `.zip`. Рядом находится файл `.sha256`. Архив содержит локализованные руководства по установке, RGB, Desktop, Changelog, Status и Review, лицензии приложения, шрифтов, иконок и eframe, сведения о происхождении прошивки, точный офлайн-каталог beta.3 и публичные IHX/map-файлы профилей, манифест исходников/бинарника и внутренний `SHA256SUMS`. Текст справки также встроен в исполняемый файл. Это неподписанные пакеты-кандидаты со скриптами явной установки и удаления для текущего пользователя. Они не включают MSI/DEB/PKG и не являются подписанной/нотарифицированной поставкой.

Для локальной упаковки используется только стандартная библиотека Python 3.11 или новее:

```sh
mkdir -p target/candidate
target/release/ak-configurator --self-check --output target/candidate/runtime-self-check.json
python3 scripts/package_ak820_candidate.py \
  --binary target/release/ak-configurator \
  --cava-helper target/release/audio/cava \
  --platform linux-x86_64 \
  --runtime-check target/candidate/runtime-self-check.json \
  --output-dir target/candidate
```

Укажите путь к бинарнику и значение `--platform` нужной цели: `linux-x86_64`, `linux-arm64`, `windows-x86_64`, `windows-arm64`, `macos-x86_64` или `macos-arm64`. Скрипт проверяет формат/архитектуру исполняемого файла и сверяет включённые публичные файлы прошивки с манифестом выпуска. По умолчанию дерево Git должно быть чистым. `--allow-dirty` предназначен только для явно обозначенного локального пробного пакета; манифест отмечает незакоммиченное состояние исходников. Перед распаковкой проверьте соседний файл контрольной суммы (`sha256sum -c <архив>.sha256` в Linux; `shasum -a 256 -c <архив>.sha256` в macOS). Затем проверьте внутренний `SHA256SUMS`. Linux: распакуйте `.tar.gz`, при необходимости разрешите запуск `ak-configurator` и запустите его. macOS: распакуйте `.app.zip` и откройте `AK-Configurator.app`; неподписанная сборка может быть заблокирована Gatekeeper и не нотарифицирована. Windows: распакуйте ZIP и запустите `ak-configurator.exe` для переносимого режима либо используйте установку для текущего пользователя ниже. Кандидаты — неподписанные пробные сборки; проверка архитектуры и хешей не подтверждает работу платформы или физической клавиатуры.

### Распаковка, проверка и запуск кандидата

Примеры предполагают, что архив и соседний `.sha256` уже получены из успешного текущего workflow или созданы локальным упаковщиком. Используется точное имя выбранной ОС/архитектуры; опубликованная загрузка кандидата не подразумевается. При несовпадении любой контрольной суммы остановитесь.

Linux x86_64:

```sh
set -e
archive=ak-configurator-0.1.0-alpha.1-linux-x86_64.tar.gz
sha256sum -c "${archive}.sha256"
tar -xzf "$archive"
cd "${archive%.tar.gz}"
sha256sum -c SHA256SUMS
./ak-configurator
```

macOS arm64:

```sh
set -e
archive=ak-configurator-0.1.0-alpha.1-macos-arm64.app.zip
shasum -a 256 -c "${archive}.sha256"
ditto -x -k "$archive" .
cd "${archive%.app.zip}"
shasum -a 256 -c SHA256SUMS
open AK-Configurator.app
```

Windows x86_64, PowerShell:

```powershell
$ErrorActionPreference = 'Stop'
$archive = 'ak-configurator-0.1.0-alpha.1-windows-x86_64.zip'
$expectedHash = ((Get-Content -LiteralPath "$archive.sha256") -split '\s+', 2)[0]
$actualHash = (Get-FileHash -LiteralPath $archive -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actualHash -ne $expectedHash) { throw 'Archive SHA256 mismatch' }
Expand-Archive -LiteralPath $archive -DestinationPath .
Set-Location ($archive -replace '\.zip$', '')
Get-Content -LiteralPath SHA256SUMS | ForEach-Object {
    $expectedHash, $relativeFile = $_ -split '  ', 2
    $actualHash = (Get-FileHash -LiteralPath $relativeFile -Algorithm SHA256).Hash.ToLowerInvariant()
    if ($actualHash -ne $expectedHash) { throw "SHA256 mismatch: $relativeFile" }
}
Start-Process .\ak-configurator.exe
```

### Установка, обновление и удаление для текущего пользователя

После проверки и распаковки пакета полностью завершите приложение и помощник командой **Выход**. Из директории распакованного пакета выполните подходящую команду:

| Платформа | Установка или обновление | Путь установки |
| --- | --- | --- |
| Linux | `sh ./install-user.sh` | `${XDG_DATA_HOME:-$HOME/.local/share}/ak-configurator/current`, постоянная ссылка в `${XDG_BIN_HOME:-$HOME/.local/bin}` и пункт меню приложений |
| macOS | `sh ./install-user.sh` | `~/Applications/AK-Configurator.app` |
| Windows PowerShell | `powershell -NoProfile -File .\install-user.ps1` | `%LOCALAPPDATA%\Programs\AK Configurator` и ярлык в меню «Пуск» |

Скрипты проверяют пакет до замены, подготавливают новую версию отдельно и сохраняют прежнюю установку до переключения. Они не запускают программу, не включают автозапуск и не меняют отдельные настройки приложения и копии клавиатуры. В Linux бинарник устанавливается по постоянному пути `current`, поэтому существующая регистрация автозапуска продолжает выбирать обновлённую программу. Ограничения ОС на неподписанные приложения и скрипты сохраняются; скрипты кандидата не подписаны.

Для удаления выполните `sh ./uninstall-user.sh` в Linux/macOS или `powershell -NoProfile -File .\uninstall-user.ps1` в Windows. Используется копия, сохранённая при установке, либо распакованный пакет. Удаление запрашивает подтверждение перед очисткой принадлежащих установке файлов; настройки приложения, кэш и отдельно сохранённые резервные копии остаются. Существующая регистрация автозапуска ОС не отключается: перед удалением выключите **Запуск при входе в систему** в приложении.

### Загрузка обновления приложения

Откройте **Об AK Configurator → Обновления приложения**, затем нажмите **Проверить обновления**. По умолчанию выбираются стабильные выпуски; для alpha или beta явно включите **Показывать предварительные версии**. **Скачать и проверить** доступно только для более новой версии. Клиент требует индекс проекта для шести целей, SHA256 файлов из GitHub и точное соответствие ОС/архитектуры. Выпуск без этих метаданных через этот путь недоступен.

Прежняя неопубликованная сборка приложения `0.1.0-beta.2` по SemVer старше `0.1.0-alpha.1`. Для перехода с неё на первую альфу скачайте и проверьте пакет альфы вручную, затем выполните описанную выше установку/обновление. Клиент обновлений намеренно не предлагает её как более новую версию.

После проверки скопируйте показанный путь к архиву, завершите приложение и помощник, распакуйте архив и выполните установку для текущего пользователя по таблице выше. При отмене или ошибке загрузки файл не предлагается к установке. Установщик, прошивка и команды клавиатуре автоматически не запускаются. Имя архива в кэше начинается с SHA256; имя директории внутри остаётся обычным `ak-configurator-ВЕРСИЯ-ПЛАТФОРМА`. Установщик приложения сохраняет настройки помощника.

### Офлайн-проверка бинарника и подготовка выпуска

`./ak-configurator --self-check --output check.json` проверяет встроенные публичные исходники/настройки по умолчанию и создаёт отчёт без чтения настроек, GUI, обращения к устройству или сети. Выходной путь должен быть новым. В Windows используется `.exe`, внутри приложения macOS — `AK-Configurator.app/Contents/MacOS/ak-configurator`. Команда проверяет выполнение пакета и не заменяет приёмку GUI или клавиатуры.

Шесть нативных заданий workflow запускают свой бинарник, включают его точный отчёт в пакет и выполняют платформенные тесты. Общая проверка сверяет полные архивы и создаёт `app-update-index.json` вместе с `release-manifest.json`. Workflow сохраняет артефакты и не публикует выпуск. При последующей публикации приложения нужно включить точные шесть архивов и `app-update-index.json` под совпадающим тегом версии; GitHub должен сообщать их SHA256. Индекс создаётся только после общей проверки. Подпись/нотаризация и физическая приёмка остаются отдельными условиями выпуска.

### Запуск помощника раскладки OS

Сначала включите **Индикатор раскладки OS** и сохраните сопоставления EN/RU в приложении. Помощник включается явно; установка или распаковка пакета сама по себе не запускает HID-индикацию. Явный фоновый запуск из распакованной директории:

| Платформа | Команда |
| --- | --- |
| Linux | `./ak-configurator --ak820-helper` |
| Приложение macOS | `./AK-Configurator.app/Contents/MacOS/ak-configurator --ak820-helper` |
| Windows PowerShell | `.\ak-configurator.exe --ak820-helper` |

`--minimized`/автозапуск при явном включении также входят в helper. **Закрыть интерфейс, оставить помощник** или обычное закрытие при включённом помощнике освобождают GUI и оставляют малый цикл; повторное открытие приложения создаёт интерфейс в том же процессе. Явный выход завершает приложение. Неизвестная раскладка снимает индикацию; ошибка устройства останавливает обновления без слепого повтора. Помощник проверяет точную прошивку и уступает владельца настройкам/копиям/восстановлению/установке. Физические тайминги раскладки/LED, передача управления GUI и ресурсы платформ требуют отдельной квалификации.
