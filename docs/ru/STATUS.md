# Состояние проекта

Обновлено 2026-10-25. Нативная разработка ведётся в `desktop-dev`, версия
приложения — `0.1.0-alpha.1`. Основа — Entropy
`5b222b5d6349fb351f53b36c66169095b3039fc1`; история и лицензии сохранены.
Браузерный этап начинается после достаточно работоспособной десктопной версии.

## Реализовано в десктопной версии

Исполняемый файл и окно называются AK Configurator. Настройки, кэш и резервные
копии используют отдельный каталог `ak-configurator`. Унаследованный механизм
обновления не скачивает Entropy вместо этого приложения; при запуске глобальные
перехватчики набора не включаются. Встроена русская и английская справка с
описанием поддерживаемой прошивки и ограничений.

Проводной путь AK820 принимает только полную постоянную v0.6.0-alpha.3 из
`dvino/ak820`, коммит `8ffa3e6`. USB ID и Vial UID определяют кандидата, но не
разрешают редактирование. При подключении проверяются VIA/Vial, манифест и
SHA-256 фактически прочитанных байтов CODE в `[0x2800, 0xC700)`. Затем читаются
все обязательные настройки, и только после этого разрешается запись. Точные
идентификаторы находятся в [каталоге](../../assets/ak820/catalog.json).

| Раздел | Реализованное поведение |
| --- | --- |
| Раскладка | Все 6 слоёв, 83 физические клавиши, маска матрицы, оба направления энкодера |
| Назначения | Проверка кодов по прошивке; неподдерживаемые и разрушительные новые действия заблокированы |
| Макросы | 16 слотов, 8192 байта, ASCII и команды Vial 1–7; полная проверка, явная разблокировка, запись блоками и точное итоговое чтение |
| Combo | 8 записей, две различные поддерживаемые входные клавиши, допустимый выход, фиксированный интервал 40 мс |
| RGB | Off, Direct, Solid, Breathing, Cycle all, Cycle left/right и Reactive; яркость до 160; проверка сохранённых данных |
| Ошибки | Одна попытка на запрос AK820; таймаут, ошибка хранилища или несовпадение чтения блокируют сессию до явного перечитывания |
| Доступ в Linux | Установщик правила hidraw только для USB `320f:505b` |
| Офлайн-проекты | `--demo-ak820` открывает девять примеров с назначениями по профилю, макросами/Combo/RGB и панелями schema03 без поиска устройств и HID |

Подключение выполняется чтением: оно не запускает разблокировку, не
переименовывает слои, не инициализирует отсутствующие настройки и не записывает
значения по умолчанию. Неизвестный, пользовательский, пробный или несовпадающий
образ отклоняется; приложение не открывает для него рабочий редактор.

## Границы проверки

Десктопный исполняемый файл Linux x86_64 собран Rust 1.97.0 и запущен в
изолированном Xvfb с `--demo-ak820`. Офлайн-тесты протокола проверяют обязательные
чтения, неверные ёмкости, повреждённые ответы, проверочное чтение после записи,
ограничения макросов, блокировку и остановку после ошибки. Отрицательные
фикстуры проверки прошивки отклоняют пробный манифест, неизвестный образ и
синтетический CODE, не соответствующий известному манифесту. Успешная фикстура
загрузки настроек начинается после проверки образа и не доказывает чтение
реальной прошивки по USB.

Результаты тестов и независимого ревью находятся в [REVIEW.md](REVIEW.md).
Команды физической клавиатуре, прошивка, сброс, разблокировка и проверка
сохранности после отключения питания не выполнялись. Модель протокола и
просмотр интерфейса не заменяют аппаратную проверку.

Workflow `desktop-dev` описывает шесть бинарников разработки с SHA-256:
Linux и Windows x86_64/arm64, macOS arm64/x86_64. Базовый commit `7b88d59`
успешно прошёл run `40168550192`; скачанные файлы проверены по checksum
и архитектуре бинарников. Это доказательства для указанной базы, а не новых
незакоммиченных изменений или запуска на всех шести платформах.

Каталог beta.1 теперь задаёт размеры таблиц, активные QSID, ограничения
источников кейкодов и точные идентичности настроек. Идентичность упакованного
образа есть только у `work`; у остальных она отсутствует. В деморежиме выбор
профиля открывает отдельный редактируемый пример. В пределах сессии сохраняются
слои, оба направления энкодера, макросы, Combo, RGB и активная панель schema03.
Окно локального проекта сохраняет и открывает каждый профиль в
`.ak820project.json`; весь файл проверяется до изменения состояния. Отмена
импорта возвращает предыдущий пример в пределах сессии. Файлы проектов
отделены от резервных копий прошивки.
Вне деморежима остаётся просмотр каталога. Запись настроек beta и прошивка
заблокированы; подключение принимает только точный образ alpha.3.

Новые модули копий проверяют структуру архивов, извлекают настройки из NVM
schema02/03 и сопоставляют ROM с точной квалифицированной записью каталога beta.
Типизированные кодеки сохраняют неактивные данные и соседние байты. Это основа:
сбор полной копии, история, миграция, выполнение восстановления и интерфейс
пока не завершены. Полное извлечение schema01 требует явной миграции и
отклоняется. Хеш защищённых областей определяет ревизию оборудования,
но не принадлежность конкретной клавиатуре. Положительная проверка полного
квалифицированного ROM пока не покрыта.

Офлайн-пакет прошёл полный host-набор (1593 успешно, 0 ошибок, 14 пропущено),
независимое ревью интеграции и проверки демо Linux, описанные в
[REVIEW.md](REVIEW.md). Аппаратная приёмка не заявлена.

## Что остаётся

Linux-сборка для разработки ещё не является готовым проверенным выпуском.
Нужны подтверждения запуска Windows/macOS, установщики, подпись, измерения
ресурсов, проверки чтения и записи на устройстве и сохранности настроек.
Полный backup/restore, обновление прошивки, восстановление OEM, редактор палитры
отдельных LED и системный помощник здесь пока не реализованы. Экспорт
`.entlayout` остаётся частичным снимком редактора; его импорт настроек
устройства заблокирован до проверок совместимости и сохранения данных.
Импорт локальных офлайн-проектов использует отдельный формат. Цвета Direct хранятся во
временной памяти и не считываются через API этой прошивки.

Следующий этап — загрузка настроек точного подключённого образа и модели
типизированных транзакций (оставшаяся часть 3a), полные копии/история,
миграция и защищённое восстановление (3b), затем отдельная аппаратная проверка. Реализация браузерной версии отложена. Подробнее в [плане](PLAN.md) и
[руководстве](DESKTOP.md).

Локальная приёмка исходников и пакета от 2026-10-25 описана в [REVIEW.md](REVIEW.md).
При той исторической приёмке Rust-проверки не повторялись. Текущая разработка
использует изолированный контейнер Rust 1.97.0; результаты записываются отдельно.
